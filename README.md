# Клиентские демонстрации: GitHub → GitHub Actions → GitHub Pages

Публичные статические демонстрации PLUR Peas. Репозиторий и опубликованные материалы доступны всем. Здесь нельзя хранить брифы, договоры, клиентские базы, секреты и закрытые исходники. GitHub Pages не используется для рабочих интернет-магазинов, платежей и конфиденциальных кабинетов. Регистрация доменов и DNS остаются в REG.RU; этот процесс их не меняет.

## Защита перед применением процесса

1. Включить защиту main: обязательный PR и статус validate от GitHub Actions, актуальность ветки, запрет удаления и force push. Само наличие workflow не включает правила GitHub.
2. В Settings → Environments → github-pages проверить ограничения выпуска; разрешить только main, назначить согласованного reviewer. Само имя environment не означает наличие ручного согласования.
3. Проверить MFA и права участников. Настройки аккаунтов и GitHub проверяются отдельно от кода этого PR.
4. Source в Settings → Pages должен оставаться GitHub Actions.

На GitHub Free Pages доступен для публичных репозиториев, исходники общедоступны. Сайт будет по техническому адресу github.io без покупки домена. Фактический URL берётся из результата deployment, заранее готовность адреса не утверждается.

## Подготовка изменений

Создать отдельную ветку. Для изменения уже разрешённых публичных файлов выполнить:

```powershell
.\Publish.ps1 -Message 'Update Vconsalte'
```

Скрипт откажется работать в main и при непустом индексе. При наличии локального local-projects.json копируются только файлы из security/public-files.json. Остальные материалы источника не копируются. Скрипт проверяет файлы, запускает тесты, добавляет в коммит только разрешённые публичные пути и отправляет текущую ветку. Изменения самого workflow, политики и других служебных файлов готовятся и проверяются отдельным обычным PR.

Открыть PR в main. Статус validate проверяет тесты, всю полученную историю Git и итоговую папку public через Gitleaks с маскировкой значений, состав файлов, локальные ссылки и синтаксис JavaScript. Обновления Actions предлагает Dependabot. В проекте сейчас нет прикладного менеджера зависимостей; при его появлении нужно добавить соответствующие проверки. Успешный PR или merge сами по себе не публикуют сайт.

## Отдельный выпуск

После принятия PR и явного одобрения публичного выпуска открыть Actions → Publish client previews → Run workflow, выбрать main, указать полный SHA принятого коммита и confirmation: PUBLISH. Несовпадение SHA или другая ветка блокируют выпуск. Артефакт строится и сканируется заново, затем выполняется deploy с минимальными правами и проверка опубликованных файлов по SHA-256 без авторизации.

Для нового файла или проекта нужен пересмотр security/public-files.json с подтверждением разрешения на публичность. Список ограничивает пути, но не определяет конфиденциальность содержания: ручная проверка и сканер нужны дополнительно. Разные пути одного сайта не изолируют данные клиентов в браузере.

## Откат и ограничения

Если проверка после deploy не прошла, файлы уже могли стать доступны. Автоматического отката нет. Создать PR с revert проблемного изменения, пройти validate, принять PR и отдельно выпустить новый SHA. При утечке ключ сначала отозвать; удаление файла не удаляет его из истории и чужих копий.

Gitleaks не доказывает отсутствие персональных данных или всех видов секретов. Проверка синтаксиса не является аудитом приложения. Для JavaScript/Python и будущей серверной части подключать анализ кода и проверки доступа по модели угроз. Резервные копии данных, защита платежей и противодействие DDoS не обеспечиваются этим workflow.
